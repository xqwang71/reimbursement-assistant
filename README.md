# 报销助手开源版

在自己的电脑上核对票据、匹配经费、填报上经贸大学的报销单，并把学校导出表汇总为项目执行看板。Mac 和 Windows 共用一套程序。首次打开可直接试用虚构报销汇总。

## 打开助手

1. 安装 [Node.js 22.13 或更新版本](https://nodejs.org/)和 [Python 3.11 或 3.12](https://www.python.org/downloads/)。Windows 安装 Python 时建议启用 Python Launcher 或加入 PATH。
2. 解压整份源码。Mac 双击 `打开报销助手.command`，Windows 双击 `打开报销助手.cmd`。也可在该文件夹的终端运行 `npm run launch`。首次启动需联网安装 Node.js 依赖和 Excel、PDF 读取组件。
3. 如果浏览器未自动打开，使用启动窗口显示的本机地址，默认是 [127.0.0.1:3033](http://127.0.0.1:3033/)。关闭启动窗口会停止本机服务。更新程序后，如果启动器提示旧程序仍在运行，请在原启动窗口按 `Ctrl+C`，再打开助手。

正式填报时，Mac 使用 Chrome，Windows 可使用 Chrome 或 Edge。需指定浏览器时，可在启动前设置 `REIMBURSEMENT_BROWSER_BIN` 为浏览器可执行文件的完整路径。

## 试用示例

首次打开会显示 2026 年的虚构数据，可在「使用人与年度」切到 2027 年。展开项目可以追溯到 Excel 的表名和行号。示例可以查看、下载和导出，学校登录、同步和填报在个人目录中使用。

| 文件 | 用途 |
| --- | --- |
| `YYYY年度进账与报销台账.xlsx` | 项目经费汇总模板，含「年度汇总」「项目清单」「学校项目匹配」「代人报销分配」 |
| `报销单统计.xlsx` | 智能报销导出格式 |
| `报销单查询.xlsx` | 日常线下预约报销导出格式 |
| `学生劳务费导出.xlsx`、`校外人员劳务费导出.xlsx` | 薪酬申报导出格式 |

在「数据来源与导出」可下载台账和样表，源码里的样例在 `examples/2026/` 和 `examples/2027/`。制作自己的台账时，把模板另存到自己的年度目录，换成自己的数据，并按年度命名为 `YYYY年度进账与报销台账.xlsx`。项目清单使用学校项目编号关联导出表。

## 使用自己的票据

1. 点「设置我的报销」，输入使用人名称、年度和已有票据文件夹的完整路径。以后从「使用人与年度」打开该年度。工作清单显示正在读取的「原票据目录」，可在这里更改路径。
2. 将学校导出的 Excel 放在年度目录顶层，然后点「重新读取执行表」。按事项整理的发票、付款记录和附件放在子文件夹。需要从网页拉取导出时，点「同步学校执行表」。学校登录和校园网或 aTrust 连接由本人在同一台电脑完成。
3. 在工作清单合并同一事项的来源文件夹，填写用途、匹配经费并核对。教学和科研加签人默认留空，可在设置里添加常用姓名和工号，也可在单笔详情或薪酬申报中指定。贸大出行使用所选经费口径的常用加签人。可在「按项目指定科研经费」填写项目编号，之后保存这些项目的匹配时自动选择科研口径。
4. 点「填报选中项」。执行区逐笔显示金额、项目和审批或预约信息。核对后点「确认提交本笔」。选「先别提交」会保留原单供核对。若结果不确定，按学校原单核实再继续。

日常线下预约可在设置里选择校区和学校页面显示的支付类型。预约完成后自动保存 PDF。自动打印默认关闭，开启后使用系统默认打印机。Windows 的自动打印还需要默认 PDF 程序支持 Print 操作。

## 附件识别和外部模型

在项目目录运行以下命令，安装本机附件识别组件。

```sh
npm run launch -- --install-ocr
```

OCR 在本机运行。四个外部模型场景默认关闭。关闭时仍可读 Excel、做汇总及使用本机规则核对材料。需要提取新差旅行程时，可在设置中单独开启「差旅核对」。姓名不参与模型提取，关联学校出差申请时按页面提示核对单号。

在设置的「使用场景」为「附件识别」选择模型后，助手会根据本机提取的整批附件文字复核材料类别及付款与发票的对应关系。详情会标明使用了本机规则、模型复核还是已有的模型结果。关联待核对时，可在详情中勾选各张发票对应的付款凭证，点「保存核对结果」。普通人民币报销按每张发票金额与对应实付金额的较小值计算，再汇总用于经费分配。

可使用本机的 ChatGPT / Codex 登录，也可配置第三方模型，例如 DeepSeek API。两种方式都需要安装本机 Codex CLI。Windows 如需手动指定 Codex，将 `CODEX_BIN` 设为 `codex.exe` 的完整路径。

使用 DeepSeek 时，在 `owner/<使用人>/.env` 中设置 `DEEPSEEK_API_KEY`，退出并重启助手。在「连接与凭据」选择「DeepSeek API」，再在「使用场景」为需要开启的功能选择 DeepSeek 并保存。助手设置中填写的是环境变量名，可使用「添加连接」接入其他兼容 OpenAI Responses API 的服务。DeepSeek 的接口和模型名称见 [DeepSeek 官方文档](https://api-docs.deepseek.com/guides/responses_api/)。

启用场景前，设置页会说明发送内容。发送前会以代号替换附件名，并尽量遮盖带标签的姓名、身份证、卡号、手机号和邮箱。手写消息和 OCR 文字仍可能含其他个人信息。

## 本机数据与公开文件

程序在本机回环地址监听。发票、付款记录、年度台账和学校导出表留在所选原票据目录。`owner/<使用人>/.runtime/` 保存年度路径、识别结果、设置、待办、项目匹配、执行记录及浏览器会话。工作清单和经费汇总按选定年度读取。发票去重记录由同一使用人的各年度共用。使用外部原票据目录时，办理结果登记在工作清单，票据文件夹沿用原名。

Git 忽略整个 `owner/`，公开样例在 `examples/`。分享时请使用 GitHub 提供的源码 ZIP。更新时先退出助手，保留 `owner/`，再更新程序文件。

如果之前把票据放进了 `owner/<使用人>/<年度>/`，这些目录仍可打开。要改为读取原始目录，在该年度点「更改目录」，登记同一年度的原票据完整路径。

## 初次使用

1. **打开网页。** 下载并解压源码，按上面的「打开助手」启动。使用期间保持启动窗口开启。
2. **先看样例。** 在「使用人与年度」里选「示例」，切换 2026 或 2027。可从「数据来源与导出」下载样表。
3. **换成自己的资料。** 点「设置我的报销」，填写使用人、年度和「原票据目录」。可沿用已有文件夹，整理方法见下面的例子。
4. **先核对一笔。** 点「刷新文件夹」，在左栏勾选一个来源文件夹，点「合并为报销事项」。在右栏匹配经费，在中栏填好用途并点「保存事由」或「更新事由」，再打开「详情」核对金额和附件。需要登录学校系统时，按页面提示在本机完成登录。
5. **核对后提交。** 勾选该事项，点「填报选中项」。在「执行与互动」里核对金额、项目及审批或预约信息，确认无误后点「确认提交本笔」。智能报销点「先别提交」后，可从「继续原草稿」再次核对。若你已在学校系统作废或删除草稿，可在助手里登记结束，再移除事项或开始另一笔。

### 文件夹怎么放

以自己电脑上的 `我的报销/2026/` 为例。在「原票据目录」填 `2026` 文件夹的完整路径。下表中的文件名和金额都是示例。

| 在年度目录里的位置 | 放什么 |
| --- | --- |
| `办公用品/01-课程用文具/` | `发票.pdf`、`付款凭证.png`、`订单明细.pdf` |
| `书籍资料/02-课程参考书/` | `图书发票.pdf`、`图书付款凭证.png`、`图书订单明细.pdf` |
| 年度目录顶层 | 做报销汇总时，可放 `2026年度进账与报销台账.xlsx` 和学校导出的 `报销单统计.xlsx` 等表格 |

建议一笔报销一个最末级文件夹。把同一笔的发票、付款凭证和订单或服务明细直接放进去，有签收单或盖章清单也可一并放入。同一事项的材料已经分在几个文件夹时，可以在左栏勾选对应的来源，再点「合并为报销事项」。以后把新增材料放进原来的文件夹，点「刷新文件夹」并等核对完成。助手直接读取这个目录，识别结果和办理记录保存在使用人资料中。

例如，「课程用文具」的事由可以写「为《数据分析入门》实验课采购分组练习用文具」。如果发票是 120 元，确认对应凭证的实付是 108 元，这张发票的核定金额就是 108 元。看到「待确认对应关系」时，在事项「详情」里展开「核对发票对应的付款凭证」，勾选对应凭证，点「保存核对结果」。

### 请 coding agents 帮忙接入并检查缺项

把下面这段发给能访问你本机的 coding agent（例如 workbuddy、dsh、codex）。替换方括号里的内容，暂时不知道的可以留空。

```text
我第一次使用「报销助手开源版」，请帮我在本机接好已有票据，并带我核对一笔。

- 使用人和报销年度 [例如 示例老师，2026]
- 报销助手解压后的目录 [完整路径]
- 已有的年度原票据目录 [完整路径]
- 想先试的事项文件夹 [文件夹名，或请推荐一笔材料较齐的]

1. 先读项目的 README，检查启动和识别组件，按说明打开助手。已有的使用人与年度继续用，需要新建时从「设置我的报销」登记。核对页面显示的「原票据目录」，如路径有误，从「更改目录」选我指定的原目录。
2. 就地读取票据，票据、提取内容和办理记录都留在本机。先确认「附件识别」的外部模型已关闭，再点「刷新文件夹」。如需调整文件夹结构，先给我整理建议，等我确认后再改动。
3. 帮我核对一笔。可以在左栏把同一事项的来源文件夹「合并为报销事项」，再打开「详情」。逐张列出发票金额、对应实付和可核定金额。对应关系不清楚的标为「待我确认」，并指出要核对哪些文件。
4. 给我一份待补清单，写清缺哪份材料、需要我确认的事由或经费项目名称和编号、需要填写的加签人，以及下一步在哪个页面操作。到本机核对为止，学校登录和正式提交由我本人操作。
```

## 验证

`npm run check` 检查源码语法。运行 `npm test` 前，安装 `requirements.txt` 中的依赖及测试用的 `PyMuPDF`。服务测试用虚构材料，浏览器测试使用本机模拟页面和独立会话。GitHub Actions 配置分别在 Mac 和 Windows 运行。校园登录、真实填报和实际打印需要在相应电脑上核验。

项目为独立工具。学校系统入口、授权和报销口径以校方当前规则为准。
